## 加載圈圈顯示失敗 — 檢討與復查報告

## 問題回顧

Test 頁面的三個加載圈圈動畫從始至終無法正常顯示，經過多次嘗試終於找到根本原因。此報告詳述失敗原因、診斷過程，以及最終解決方案。

根本原因分析

1. Tailwind Color Class 不存在（最主要原因）

原始代碼使用 border-t-orange-400，但 Tailwind CSS 的 orange 色系只定義到 50, 100, 200, 300, 500, 600 ...等級，完全沒有 400。這導致該 class 從未生成 CSS，邊框顏色始終為灰色，圓形看不出任何視覺效果。

2. Tailwind Class 組合的 Purge 機制

即使改成 border-t-orange-500，仍然無法正常顯示。原因在於 Tailwind 的樹搖（tree-shaking）機制並不會生成所有 color × variant 的組合。border-t- 與 orange-500 的特定組合可能在編譯時被忽略，或被 Tailwind 的安全清單限制所排除。

3. 診斷過程的偏差

最初將問題歸咎於 animate-spin 動畫本身，花費時間在 tailwind.config.js 中重新定義 keyframes，但實際上 animation 正常，只是圓形本身看不見。誤判方向導致走了冤枉路。

4. Inline Style 的必要性

CSS framework 不應該是唯一的樣式依賴。應該在第一時間使用 inline style 屬性作為 fallback，確保關鍵的視覺效果（如邊框顏色、寬高、圓角）能夠可靠地渲染。

### 改進建議

1. CSS 優先使用 inline style 驗證 — 開發新 UI 時先用 inline style 確保視覺正確，再逐步遷移到 Tailwind
2. 定期檢查 Tailwind 文檔 — 確認可用的 color 級別，避免使用不存在的 class
3. 瀏覽器開發工具驗證 — 要檢查圓形沒出現時，先在 DOM Inspector 確認元素是否真的有色彩屬性
4. 為 Calendar 頁面修復 — Calendar.tsx 也使用了 border-t-orange-400，需要統一改成 inline style

此次失敗實質上是 假設 Tailwind class 一定存在 + 診斷方向錯誤，下次應該更謹慎驗證框架的實際功能邊界。
