### 已完成事項

- 想要排查一下現在是否有檢測當前借用比數的機制與限制，以之前沒資料庫只使用 google cal 的狀況，我猜大概率是沒有。看有沒有機會實作一個人最多同時只能借用三筆的限制，這個資料如何儲存我沒概念，使用現有的 firestore 做篩選應該就行了？ => 一個人只能借用近一個月的空間，並且雖然一次最多只能暫存三筆，但其一周內也是有辦法借用數十筆，再加上還有淡季，做太多的防檔意義不大。
  - 照片回傳機制與限制已完成，不需更多防檔，影響體驗

- 如果用戶上傳之後反悔了想要刪除 / 手滑按到隱私照片 / 有人上傳非法照片，那整體流程又要怎麼設計？還有攸關現在的資料庫設計是否有這種彈性。 => 反正只是個學校內的非正規系統，可以把彈性交給雙方：讓上傳者能刪除自己的照片，管理員能刪除任何照片。刪除後的狀態目前規劃是「照片刪除後借用退回待回報狀態，需要重新上傳」，這樣才不會讓刪除變成逃避回報的漏洞。非法照片的情況管理員直接刪除即可，對方的借用同樣退回待回報。
  - 一般使用者不能刪除自己已經開始的事件 (已經開始的事件就不會顯示刪除按鈕)，而管理員可以刪除任何事件。
  - 刪除系統已完成
