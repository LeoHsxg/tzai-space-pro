## 已確認的架構決策

桌面版最容易醜的原因＝手機單欄拉寬、中間一條、兩側大片空白。桌面要善用寬度做並排、以常駐導覽取代底部列。

1. **左側常駐側欄**取代手機底部導覽。
   - 導覽只留兩項：`借用日曆`、`空間守則`。
   - `申請借用`是「動作」不是「頁面」，抽成側欄上的**主要按鈕**（品牌色），不再是手機的浮動 FAB。
   - 側欄底部放使用者卡（點擊進入個人檔案）＋通知鈴鐺＋登出。**個人檔案不佔導覽項**。
2. **日曆首頁＝月曆 + 右側當日詳情**兩欄並排。
   - 左：放大的月曆（日格夠大放房間色點），右上放房間色圖例。
   - 右：當日詳情面板，點某天即時換成當天預約清單，可依房間篩選，底部可直接申請當天。
   - 「日曆與清單並排」是桌面相對手機最大的優勢。
3. **申請借用＝置中 modal**，蓋在變暗的日曆上（取代手機的底部彈出 sheet）。
   - 短欄位雙欄並排（姓名/手機、人數/地點、開始/結束），高度砍半免捲動；活動簡述獨佔整列。
   - 從側欄按鈕或右側面板「於此日申請」皆開此 modal，並自動帶入日期。
4. **空間守則**：借用流程改成**橫向三步**；守則與補充事項**左右雙欄**，限制閱讀寬度不拉滿。
   - `借用流程`**保留**（以現行程式碼 `src/views/Rule.tsx` 為準；行動版舊截圖沒有它是因為截圖為舊版）。
5. **個人檔案**：入口在側欄底部使用者卡。
   - 因**照片牆／照片上傳功能已移除**，不再有「待完成」欄位（原本用來提醒借用後上傳照片）；只保留 `即將到來` 與 `歷史紀錄`。
   - `即將到來`獨立整列卡片（顯示已核准、尚未開始的借用）。
   - `歷史紀錄`改用**表格**（空間／時間／狀態）呈現，可掃描、可依空間篩選、可分頁或載入更多。**不含照片欄位**。101 筆用手機式卡片一路捲很痛苦。

設計範圍（本輪 Figma）：**日曆首頁、申請借用、空間守則、個人檔案**四個畫面。

## Backlog — 已認同、但不在本輪做

以下功能使用者確認要做，但**不在這輪桌面重設計範圍內**，待桌面版基礎完成後再規劃：

### B1. 月曆「週檢視」切換
- 目前日曆首頁只有月檢視。加入月／週切換。
- 週檢視＝橫軸一週七天、縱軸時間，預約以色塊落在對應時段，一眼看出「哪個空間何時被占用」。
- 優先度：高（B2 的前置）。

### B2. 右側詳情面板 — 拖曳建立預約
- 在時間段上直接拖曳圈選來建立預約。
- **互動設計較重，需要重新規劃思考**（拖曳範圍、跨房間、與現有 modal 表單的關係、衝突檢查等）。
- **相依：需先完成 B1 週檢視**（拖曳建立通常掛在週/日時間軸上）。
- 優先度：中（排在 B1 之後）。

### B3. 房間快速篩選
- 讓使用者快速只看某一或某幾個空間的預約（日曆點、右側清單、歷史表格皆可套用）。
- 線框中已在右側面板與歷史表格示意 chip 篩選列，實作待本輪之後。
- 優先度：中。

## 下一步

3. Figma 定稿後才進入前端實作；B1–B3 另立工作項。
